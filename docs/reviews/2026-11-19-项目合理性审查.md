# 2026-11-19 项目合理性审查

审查对象：`docs/产品规划与实施方案.md`（v1.0）、`src/`（Vue 3 前端）、`src-tauri/src/`（Rust 后端）、`Cargo.toml`、`tauri.conf.json`、`package.json`。

审查维度：**规划与实现的对齐度**、**分层边界是否仍成立**、**工程完整性（测试/红线/配置）**、**契约与重复代码**。

审查方式：规划逐项对照实现 + 前后端分层与依赖方向扫描 + 行数实测 + 关键路径回读；结论由两次独立只读扫描交叉验证。本文与同目录 `2026-11-18-代码审查与整改清单.md`（安全/健壮性）、`2026-11-19-数据一致性审计.md`（缓存副本/乐观锁）互补，不重复其条目。

状态：本次为**只读审查，未改动代码**；所有问题均为 `待办`，处置后按编号回填状态。问题编号 `A-xx`（Architecture / Alignment）。

## 一、总体结论

工程骨架是合理的：前后端**主分层成立**，IPC 单出口、命令薄适配、路由作用域规范、后端错误类型统一、CSP 与 capabilities 权限面已收紧，这些在前两份审查中已确认。

本次发现的偏差集中在**"做得比文档写的多、但比文档承诺的少"**两端：

1. **文档滞后于实现** —— 规划中列为未做的构思向导其实已完整落地；反过来，规划承诺的自动更新、P8 打磨上线（测试 / README / 打包 / 端到端）几乎全部未启动，而文档里这些模块的语气是"待做"，实际连脚手架都没有。
2. **规范有红线但无自动化防线** —— 强制"单文件 ≤ 500 行"已有 3 个文件越线；"子组件只走 props/emit"已有 4 处越层；前端 0 单测，这两类违规都不会在 CI 里报错。
3. **契约与实现漂移** —— 类型声明了未实现的能力字段，JSON 解析存在两套不等价实现，启动期 DB 错误被压成 internal。

按影响排序：**A-04（P8 整体空档）> A-06（组件越层）> A-09/A-10（行数红线）> A-12（空契约）**。
