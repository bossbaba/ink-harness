## 一、总体结论

工程基础质量好于同类项目（`invoke` 单出口、路由作用域规范、无 `as any`、全量类型检查 + 单测）。

真正的问题集中在两处，本次均已处理：

1. **webview 权限面过宽** —— 曾把「任意 SQL + 任意文件写 + 密钥明文读取」三件套交给渲染进程；
2. **错误模型与状态归属松散** —— 裸 `Result<T, String>`、错误被静默降级、作品状态多副本、DB 命令占用主线程。

## 三、本次改动明细（要点）

### 安全边界

- `capabilities/default.json` 只保留 `core:default`、`core:event:default`、`core:window:default`、`dialog:allow-save`；`tauri-plugin-sql` 与依赖一并移除，数据库只经 Rust service 层访问。
- `csp`：`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self' ipc: http://ipc.localhost ws://localhost:1420 http://localhost:1420`。`style-src` 必须允许内联（Naive UI 运行时注样式）。
- 导出落盘：非空、绝对路径、扩展名白名单（md/html/epub/docx/txt/pdf）、拒绝隐藏文件、父目录 `canonicalize`（同时验证存在性与 `..` 逃逸）。
- 隐私：`project::is_local_only` 成为唯一判定；gateway 传了 `project_id` 就必须查库，且与前端声明取「或」（只能收紧）；rag 复用同一函数。

### 错误模型

- `AppError { code, message }` 直接序列化成 `{code, message}`；`From<String>` 保留既有中文文案的过渡通道（分类记为 internal），关键路径已改用带语义的构造器。
- 前端 `api/tauri.ts` 的 `call()` 统一把拒绝转成 `BackendError`（`toString()` 只返回 message，页面既有的 `String(err)` 展示无需改动）；`normalizeError` 提供错误码到「下一步该做什么」的提示。

### 数据一致性

- RAG 的两张表同库，写入改为单事务 `replace_chunks`：清旧与写新要么都成、要么都不变；`purge_source` / `purge_project` / `clear_chunks` 同样单事务。
- `delete_chapter` 三条语句包进事务；删章/删设定/删作品分别清理片段与向量（`vec_rag` 无外键，必须手工清）。
- 启动时清理历史孤儿片段。

### 并发与阻塞

- `DbState::biz()/vec()` 事务化包装 + 中毒恢复。
- 全部 DB/文件/钥匙串命令改为 `async` + `spawn_blocking`，主线程不再执行 SQLite。
- 自动保存单飞：`saving` 标记保证同一时刻只有一个请求，期间的输入留在 `pending` 由本轮循环补写，避免并发写导致旧内容覆盖新内容。

### 待人工确认

1. **CSP 对打包产物的影响**：`tauri dev` 走 `http://localhost:1420`，CSP 主要作用于打包后的自定义协议。需要 `pnpm tauri:build` 后实机打开，确认控制台无 `Refused to ...`；若有漏网来源，补进对应指令，不要整体退回 `null`。
2. **导出扩展名白名单**：新增导出格式时需同时改 `infrastructure/fs.rs` 的白名单与 `publishService` 的格式表。
3. **迁移版本号**：本次为 `SCHEMA_VERSION = 1`；老库（`user_version = 0`）首次启动会跑第 1 步（全部幂等），并把版本写回。后续改结构务必 +1 并追加步骤，不要直接改第 1 步。
4. **端到端点击**：本次只做静态检查、单测与编译；自动保存恢复提示、离开守卫、全局提示栈、路由懒加载都需在桌面应用内实际点一遍。
