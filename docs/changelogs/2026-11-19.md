## 更新内容

### 创作工作流不遵守设定库角色

- 现象：作品设定库里是「张三 / 李四」，工作流「策划」生成的方案和「写作」生成的正文却自创了「林深 / 零号」等角色。
- 根因有两条：① `buildStageMessages` 只有写作/审稿把 `context`（作品上下文）拼进提示词，策划/编辑/出版三个阶段完全没带设定库；② Rust 侧 `outline_context` 组装设定条目时只读 summary / 别名 / 时间 / 关系，**丢掉了表单里的「补充备注」**——性格、外观、背景这些角色信息正是写在这里。
- 修复：所有五个阶段共用 `SETTING_RULE`，明确「沿用设定库已登记姓名、别名与关系，不得自创关键角色或改名」；策划/编辑/出版的 user 消息补上 `【设定与大纲】` 上下文；`ElementBrief` 新增 `notes` 字段，`build_context` 输出「补充备注」。
- 验证：用更新后的写作提示词直连本机 Ollama 实测，710 字正文中「张三」4 次、「李四」3 次、「林深 / 零号」0 次；Rust 单测 85 通过 / 2 忽略（新增补充备注进上下文用例）；`cargo check`、`pnpm typecheck`、`pnpm check`、`pnpm build` 均通过。

### 思考型模型返回空内容

- 现象：工作流（以及所有走同一网关的 AI 功能）点「运行本阶段」后固定报「模型没有返回内容，可以再试一次。」，换提示词无效。
- 根因：默认模型 `qwen3.5:4b` 是 thinking 模型。Ollama 的 `/v1/chat/completions` 把它生成的全部文本放进 `delta.reasoning`，`delta.content` 始终为空；Rust 侧 `extract_delta` 只读 `content`，于是前端累计到 0 字，抛 `EMPTY_REPLY_MESSAGE`。用工作流「策划」提示词直连复现：reasoning 9668 字、content 0 字。
- 修复：本地 Ollama（默认端口 11434）改走原生 `/api/chat` 并显式传 `think: false`——原生接口实测输出 740 字合法 JSON、0 字 thinking；新增 JSONL 流式解析器与原有 SSE 解析器按 Provider 方言切换，用量统计沿用 Ollama 原生计数字段。其他 Provider 行为不变。
- 验证：`cargo test --lib` 84 通过 / 2 忽略；新增真实 Ollama 端到端用例（ignored，手动执行）拿到正文与 token 用量；新增 3 个解析器单测；`cargo check` 通过。

### 默认模型设置与顶栏当前模型标识

- 新增 `SETTING_DEFAULT_MODEL`（`default_model`）设置项。模型管理页「任务路由」增加「默认模型」下拉：候选为已启用 Provider 下的全部模型，值沿用 `providerId:modelId`，与 RAG 模型选项口径一致；清除后回到按策略自动选。
- `modelRouter` 的 `select()` 在打分前优先命中默认模型（仍需满足当次隐私与上下文窗口约束），否则回落原有质量 / 成本 / 隐私打分；`refresh()` 一并读取默认模型，改策略或改默认模型后立即重算 `currentModel` 并通知订阅者。
- 顶栏经 `useCurrentModel()` 读取 `modelRouter.currentModel`，展示可点击的当前模型 Tag；tooltip 给出本地 / 云端与模型 ID，点击跳转模型管理。`App.vue` 启动时主动 `refresh()` 一次，无需先进入模型管理页才有值。
- 已选默认模型若被删除或 Provider 停用，设置页给出提示并说明已暂时回落，避免静默按策略选模型而用户不知情。

- 验证结果：`pnpm typecheck`、`pnpm check`（157 文件）、`pnpm build` 均通过；确认构建产物中 `.routing__default[data-v-…]` 等选择器作用域正确。
