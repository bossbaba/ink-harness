### feat：评测可信度（章节可选 / 回归对比 / 按作品过滤）

- 背景：盘点设计文档，发现要素表严重过期（Agent Loop / Tools / Action Executor 标缺失但 P1/P2 已落地、会话表与真实审计都已具备），真正未落地的是评测可信度——章节写死第一项、无回归对比、历史不按作品过滤、`propose_review` 永久排除。已同步重写设计文档 1.2 要素表为代码现状。
- 章节可选：评测页加载所选作品的章节列表供指定，默认第一项；选「不指定章节」时读章节用例自动跳过，不再写死 `snapshot.chapters[0]`。

- 按作品过滤：后端 `list_runs` 加可选 `project_id` 参数（SQL 用 `?1 is null or project_id = ?1`），IPC / tauri.ts / service / composable 全链路透传；切作品时重取该作品的章节与历史，基线不再串台。
- 回归对比：本次结果与上一次通过率差值用 NTag 显示，下降用 warning 色告警；历史每条同时显示相对前一次的差值。基线在本次落库前取，避免差值为 0；通过率口径统一到 `passRate()`。

### feat：审批结果回执与中间状态提示

- 回灌模型：作者通过/驳回写操作后，`useAgentActions` 把完整动作返回给面板，`useCopilotMessaging.appendToolDecision` 追加一条带「工具回执」前缀的 assistant 消息进入对话历史——模型在下一轮据此知道工具真的执行了还是被驳回，不再出现「我只提交了审批、不知道作者做了什么」的失忆式回答。
- 为什么不用 tool 角色：`CopilotMessage` 不保存 `tool_calls` / `toolCallId`，若发 tool 角色消息，上游会因找不到对应调用而拒绝请求（Ollama 原生协议尤甚）；回执走 assistant 角色 + 明确前缀，作者也能一眼看出不是模型自己说的话。不自动重启 Loop，避免作者点完审批被意外触发新一轮调用。
- 提示词同步：`approvalPrompt` 从「作者的决定不会自动回填」改为「结果会以工具回执出现在对话中」，模型能正确预期后续信息。
- UI：`approved` 到 `applied` 之间可能要写库，审批卡片显示「正在执行…」，不再看着像卡住。
- 验证：`pnpm check:all` 全绿（typecheck / lint / 规范守卫 / 74 单测 / build）；新增 3 例单测（队列跨上下文隔离、异上下文无法审批、批准失败落 failed 并保留原因），`cargo test --lib` 135 通过 / 0 失败。
