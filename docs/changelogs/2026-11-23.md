### feat：Agent 自主规划 Planner

- 背景：设计文档把 Planner/Controller 列为「仅任务→模型路由、无自主规划」，本轮补上任务分解与重规划，让 Agent 真正会规划；写操作仍走作者审批，保持人在环路。
- 新增 `services/agentPlanner.ts`：规划器先输出 `{"steps":[{title,intent}]}` 拆成最多 5 步（小模型执行不完更多），用现有 `parseLooseJson` 容错代码块/散字；模型可用两个元工具——`update_plan` 标记步骤完成（不可变更新并通知 UI）、`replan` 按「已完成事实 + 原因」请求重拆，默认最多重规划 1 次。
- `agentLoop` 接入：循环前先规划并把计划注入每轮 system；元工具不进全局注册表，由 Loop 拦截执行，业务工具仍走执行器；带元工具的轮次豁免空转检测（`update_plan` 每轮参数本就不同），首轮强制取数只在真正调了业务工具后才关闭；规划失败/格式不对时降级为普通循环，不影响既有问答与评测；规划调用记 `phase=plan`、`iteration=0` 的轨迹，token 与耗时照常计入看板。
- 拆分降行数：`useWritingCopilot.ts` 495 → 242 行——发送编排下沉到新 `useCopilotMessaging.ts`（持有消息流与计划状态）；`agentLoop` 的规则/解析纯函数拆到 `agentLoopRules.ts`，主文件 531 → 436 行，全部守住 500 行红线。
- UI：Agent 工具行新增「自主规划」开关（打开时顺带开 Agent 模式，避免开关看着开了却不生效）；对话区渲染计划清单（版本、步骤状态、重规划原因）；Trace 面板把 iteration=0 标为「规划」而非「第 0 轮」。
- 验证：`pnpm check:all` 全绿（typecheck / lint / 规范守卫 / 71 单测 / build），前端单测新增 16 例（解析容错、步骤上限、非法步骤拒绝、失败降级、计划注入、update_plan 推进、replan 版本递增与轨迹）；`cargo test --lib` 135 通过 / 0 失败（后端未改动，回归验证）。
