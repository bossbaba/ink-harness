### 修复：对话返回 400 invalid model name（531e438）

**现象**：写作台点「AI 对话」发问，模型返回错误 `400 Bad Request: {"error":{"message":"invalid model name",...}}`，气泡显示「这次没有拿到回答」。截图里已注入上下文 165 字，说明请求已经打到上游，问题在模型名。

**原因**：前端路由用 `providerId:modelId` 标识模型（如 `ollama-local:qwen3.5:4b`，见 `services/modelRouter.ts` 的 `${model.provider}:${model.id}`），但 `services/gateway.rs` 的 `stream_chat` 只拿这串去**定位 Provider**，随后仍把 `params.model` 整串塞进请求体的 `model` 字段。Ollama 收到 `ollama-local:qwen3.5:4b` 这种名字，只认得出「没有这个模型」，于是回 400。写作辅助、构思向导走同一条链路，同样受影响。

**修复**：

- `resolve_provider` 改为返回 `ResolvedProvider { provider, api_key, model }`，`model` 是剥掉 `providerId:` 前缀后的真实模型名，请求体用它。
- 新增纯函数 `split_model_ref`：只按**第一个**冒号切一次——Ollama 的模型名自身带冒号（`qwen2.5:7b`、`qwen3.5:9b-mlx`），按普通 `split(':')` 取第二段会把 tag 截断成不存在的模型。
- 新增纯函数 `locate_provider`：保留旧调用（只给模型名）的回退链「以 provider id 开头 → 本地 Provider → 任意启用 Provider」，但**前缀写了却不存在 Provider、整串又不是已登记模型名时直接报错**，不再悄悄回退到本地 Provider、把 `typo:model` 当模型名发给上游。

**验证结果**

- 新增 5 项单测：冒号拆分保留 Ollama tag、剥前缀、裸模型名回退、未知前缀拒绝、回退时跳过未启用 Provider。
- `cargo test` 46 例通过（41 → 46，含 2 双连接 + 3 vec）；`cargo clippy --all-targets` 无 `useless_vec` 等新告警。
- 真机实证（本机 Ollama + `qwen3.5:4b`）：修复前 `{"model":"ollama-local:qwen3.5:4b"}` → `HTTP 400 invalid model name`；修复后 `{"model":"qwen3.5:4b"}` → `HTTP 200` 并正常返回内容。验证用的 `ollama serve` 已停止，无残留进程。
- 需重启桌面应用（重建 Rust 侧）后生效，前端热更新不覆盖。

**顺带**：`services/project.rs` 测试里的 `&vec![0.0; N]` 改成切片 `&[0.0; N]`，清掉既有 `clippy::useless_vec` 告警。

### 退出时停止本地模型（b7430db）

**后端（Rust）**

- `services/ollama.rs`：spawn `ollama serve` 后记录 PID（模块级 `Mutex<Option<u32>>`）；`stop_spawned()` 退出时只停这一个实例。
- 防误杀：动手前用 `ps -p <pid> -o comm=` 确认该 PID 仍是 ollama——PID 可能已被系统回收给别的进程，不能盲杀。
- 停止用 SIGTERM（Unix）/ `taskkill`（Windows），不引入 libc/额外依赖；桌面版 App（`open -a Ollama`）由系统托管，不在记录范围，退出时不动。
- 新增 `services/setting.rs` 与命令 `get_app_setting` / `set_app_setting`：复用 `app_meta` 键值表，布尔统一存 `"1"`/`"0"`，默认值由调用方给（无需种子数据）。
- `lib.rs`：改为 `.build()?.run(|_, event| ...)`，在 `RunEvent::Exit` 读取设置并调用 `stop_spawned()`；读设置失败按默认「停止」处理，宁可多停自己起的服务，也不留后台进程。
- 新增 4 项单测：缺 key 回落默认值、覆盖写入不产生重复行、没有记录 PID 时不动作、PID 被复用时（用 `sleep` 冒充）不误杀。

### 修复：作品内二级页面宽度塌陷（b7430db）

**现象**：进入作品的构思向导/设定库/大纲后，页面缩成一百多像素的窄条，标题与正文一个汉字一行；写作台不受影响。

**原因**：写作台上线时把 `ProjectShellView` 的 `__body` 改成了 `display: flex; flex-direction: column`。二级页面根节点普遍用 `margin: 0 auto` 居中，而 flex 子项的 `align-self: stretch` 只在交叉轴 margin 不是 `auto` 时生效——auto margin 让这些页面退化为 shrink-to-fit；又因为页面根节点带 `container-type: inline-size`（尺寸包含），内在宽度为 0，最终只剩 padding 撑出的窄条。

**修复**：`__body` 只保留 `flex: 1; min-height: 0`（作为 flex 子项撑满剩余高度），不再充当 flex 容器。写作台需要的 `height: 100%` 依旧成立——百分比高度对「flex 子项撑出的确定高度」有效；其余页面恢复成普通块级流，`max-width + margin: 0 auto` 正常居中。

**验证**：`vue-tsc --noEmit`、`biome check .`、`pnpm build` 通过；页面宽度回归由 `margin: 0 auto` 的正常块级行为保证。
