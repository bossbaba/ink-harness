### 修复保存类请求与 `cargo test` 卡死（`DbState::biz()` 重入死锁）

- 现象：`cargo test` 跑起来永不返回，前端保存角色 / 构思草稿 / 评测结果时界面一直转圈，且没有任何报错。定位到两个各挂了 1 小时以上的 `cargo test` 残留进程，卡在 `services::agent_eval::tests::save_and_list_runs`。
- 根因：`DbState::biz()` 返回不可重入的 `MutexGuard`，三个函数在**持有连接的情况下**又调用了内部同样取锁的读函数，同一线程第二次 `lock()` 永久阻塞——不是报错，所以看上去只是"很慢"。
  - `agent_eval::save_run` → `get_run`
  - `agent_role::save_role` → `get_role`（插入、更新两条路径都会踩）
  - `ideation_draft::save` → `load`
- 修复：写入放进独立作用域，写完先释放锁再读回；三个函数各补注释说明"锁不可重入"，避免以后被写回去。
- 验证：`cargo test --lib` **133 passed / 0 failed**（0.43s 跑完）、零 warning；此前未确认的 guardrails 4 例、ideation 3 例、本次新增的 `native_messages_*` 2 例全部通过。

### Agent 工具调用失效与空转

- 现象：Agent 评测 5 条用例 `calls: []`，模型直接凭空白上下文编答案；偶有调用时第二轮请求 400。
- 三个独立原因，逐条修：
  1. **提示词没提工具**：system 只写了「上下文没有的信息就说未设定，不要编造」，模型据此把空白上下文当成"作品没有内容"。`buildToolRule` 改为强制先取数（含"出现具体人物而本轮没调工具就是编造"的自检），工具清单从只列名字改为「名字 + 用途」，并点明「读正文用 read_chapter、找资料用 search_notes」；空上下文占位改成「设定与大纲未在本段展示，必须调用工具读取，不能据此判断作品没有内容」。
  2. **首轮不取数**：新增 `requireToolFirst`，首轮下发 `tool_choice: required`，若模型仍直接作答则补一条追问再试（只补一次，不无限追问）；拿到首次工具结果后即关闭强制，避免多轮被迫空转。链路打通 `ChatParams.toolChoice` → `modelRouter` → `aiChat` → `agentLoop`，Rust 侧仅在 `tools` 非空时下发。
  3. **原生协议不兼容**：前端按 OpenAI 习惯把 `assistant.tool_calls[].function.arguments` 传成字符串，Ollama 原生 `/api/chat` 只认对象，直接 400（`Value looks like object, but can't find closing '}' symbol`）→ 第二轮必挂。`gateway` 新增 `native_messages()` 按方言转成对象，解析失败退化为空对象而不是让整轮失败。
- 参数容错：`validateArgs` 对 `null`/`undefined` 视为「未提供」（模型把不传写成 null 曾被记成"工具执行报错"）；`read_chapter` 的 `withContent` 接受 `"true"`，`chapterId` 猜错时回退当前章节并说明。
- 空转策略：同一组调用**第一次重复**不再直接终止，而是回填「已用相同参数调过、请换工具」的提醒（不重跑工具），连续两次重复才判 `idle-loop`。
- 实测（本地 qwen3.5:9b-mlx）：原提示 1/5 命中工具 → 强化规则 3/5 → 加 `tool_choice` 4/5 → 再加补问 **5/5**。
- 验证：前端新增 3 例锁「补问后拿到工具」「补问只补一次」「null 参数不再报错」；`cargo test` 133 全绿。

### 输入框快捷操作与 Agent 下移

- 输入框支持 `@` 直接打开引用面板、`/` 打开 Agent 菜单：快捷符会从草稿里摘掉，不留残字；邮箱（`name@`）、协议头与路径（`http:/`、`a//`）、粘贴与输入法整串上屏都不触发，`Esc` 收起面板并把焦点还给输入框。
- Agent 模式开关与角色选择从消息流搬到输入框下方工具行（`AgentBar.vue`：`＠ 引用 | Agent · 角色名 | 发送`），选角色会自动开启模式；审批卡片（通过/驳回/插入正文）仍留在对话流——那是"上一轮发生了什么"。
- `WritingAiPanel` 拆出 `CopilotComposer.vue`（494 → 437 行），输入区独立管理草稿、双快捷符与两个面板。
- `CopilotReferencePicker` 改 `defineModel` 受控展开：原先手写 `emit("update:model-open")` 与 `v-model:model-open` 监听的 `update:modelOpen` 对不上，表现为"点了没反应"。
- 踩坑记录：`vite-plugin-biome`（`applyFixes: true`）把 `import CopilotComposer` 自动改成 `import type ...`（因为当时用 `InstanceType<typeof CopilotComposer>` 取 ref 类型），类型导入被擦除后组件未注册，界面表现为"输入框凭空消失"，控制台只有一句 `Failed to resolve component`。改用结构化 ref 类型（`ref<{ setDraft: (text: string) => void } | null>(null)`）并加注释，避免复发。
